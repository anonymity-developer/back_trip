# DB 확장 실제 검증 결과

2026-11-06(KST) 작업용 격리 환경에서 확인한 기록이다. `docs/db/04-test-plan.md`의 계획 전체가 자동으로 통과했다는 뜻은 아니다.

이후 공통 설정 통합 시 기본 MySQL 3306/enjoytrip에도 앱 데이터를 준비하고 18080 앱을 루트 `.env` 하나로 재기동했다. 기존 members는 보존했다. 같은 설정으로 정합성 오류 0·테스트 9건·HTTP PASS 5개를 재확인했다. 아래 포트·측정·캡처는 최초 격리 검증 시점의 기록이며 현재 실행법은 [직접 테스트 안내](reference/local-run.md)를 따른다.

## 최종 제출 환경·파일 검증

- 공통 `.env`의 MySQL 3306/enjoytrip·앱 18080에서 19장을 새로 캡처했다. 촬영 기준 관광지 51,622건·뉴스 10건이며 시연용 회원·계획·Hot Place·게시글은 실제 화면에서 등록했다.
- `EnjoyTrip_db.mwb`는 설치된 MySQL Workbench의 SQL 파서로 실제 생성했다. 파일을 Workbench에서 다시 열어 enjoytrip 스키마 하나·테이블 12개·다이어그램 표 12개·FK 12개를 확인했다.
- `EnjoyTrip_db.png`는 같은 Workbench 다이어그램에서 네이티브 PNG로 내보냈다. 표 이름·컬럼·관계 표시를 시각 점검했다.
- `EnjoyTrip_db.sql`은 전체 DDL과 공개 기준정보·관광지·관광 사진 데이터만 포함한다. 별도 빈 검증 DB에 적재해 12개 테이블·관광지 51,622건·시도 17/구군 234/유형 8·회원 0건을 확인했다. 실제 회원·관리자·비밀번호 해시·개인 콘텐츠는 내보내지 않았다.
- 현재 관리자 화면의 실제 수집 상태는 관광지 11,669건 저장 완료, RSS 3곳에서 새 기사 10건 수집이다. 이 수집 처리 수와 전체 관광지 51,622건을 구분한다.
- 브라우저에서 날씨와 일출/일몰 HTTP 200·실제 표시를 확인했다. 충전소는 별도 요청에서도 20초 안에 완료되지 않아 성공으로 기록하지 않았다.
- [캡처별 실제 조건](screenshots/capture-manifest.json), [필수 SQL 검증 결과](submission-validation.json), [최종 제출 점검](submission-checklist.md)을 함께 제공한다.
- 배포 ZIP 하나에 DB 산출물과 `dbtrip/` 소스를 함께 담는다. 이전 `back` 자료·`.git`·`bin`·실제 `.env`·빌드 결과를 제외하고, Markdown 상대 링크와 압축 무결성을 검사했다.
- 최종 통합 ZIP을 별도 폴더에 압축 해제하고 `dbtrip/`에서 Maven `package`로 `enjoytrip.war` 생성을 확인했다. 추출본에서 기본 테스트 8건 통과·DB 통합 1건 생략을 확인했으며, 이는 앞서 공통 환경에서 실행한 DB 통합 테스트 결과와 구분한다.

아래 환경·수치·6장 캡처 서술은 최초 개발 검증 기록이다. 현재 제출 화면은 위 공통 환경의 19장으로 교체했다.

## 검색 측정

관광지 50,915건의 로컬 HTTP 응답을 각 5회 측정했다. JSP·DB 처리와 응답 본문 수신을 포함하며 브라우저 이미지·지도 타일 로딩은 포함하지 않는다. 동시 부하·운영 SLA·외부 API 지연을 검증한 수치가 아니다.

| 경로 | 표본 5회(ms) | 중앙값(ms) |
| --- | --- | --- |
| `/attractions` | 99.86, 86.23, 87.37, 97.62, 100.42 | 97.62 |
| `/attractions?region=1&type=39` | 45.15, 36.48, 40.30, 45.00, 44.32 | 44.32 |
| `/attractions?page=100` | 195.11, 178.29, 178.35, 171.29, 198.21 | 178.35 |

지역·유형 조건의 실제 EXPLAIN에서 `type=ref`, `key=idx_attractions_filter`, 예상 행 2,326을 확인했다. 이 결과만으로 모든 LIKE·전체 목록·후반 페이지가 같은 인덱스를 쓴다고 일반화하지 않는다. 근거 없이 인덱스를 추가하지 않았다.

## 남은 확인과 재현 방법

- 최초 격리 검증에서는 키 없는 날씨 503과 저장된 화면 유지를 확인했다. 이후 공통 환경에서 실제 수집·날씨·일출 응답을 위와 같이 추가 확인했다. 충전소 실연동은 응답 지연으로 남아 있다.
- MySQL 8.4에서의 실행은 미실시다. 제공 비고유 FK는 복합키로 개선했지만 실행 검증 결과를 8.4 통과로 확대하지 않는다.
- 공통 설정 통합에서 기본 DB를 사전 백업하고 기존 members를 보존한 채 새 앱 테이블·데이터를 준비했다. 별도 배포 서버나 실제 기관 연동까지 검증한 것으로 확대하지 않는다.
- 실제 사진 파일이 있는 운영 환경의 복구는 미실시다. 검증용 DB 백업·테이블·계획/관광지 참조 복원을 확인한 범위와 구분한다.

재현 명령·기대값은 [직접 테스트 안내](reference/local-run.md)에 있다. DB 산출물과 `dbtrip/` 소스는 같은 ZIP에 포함한다.
