# 구현·검증 기록

## 2026-10-30 로컬 연동 보완

- 공공데이터포털 인증키가 이미 URL 인코딩되어 있어도 요청 시 한 번만 인코딩되도록 수정했다. 관광지 수집 실패는 관리자 화면에 HTTP 상태·API 오류 코드·연결 실패 유형으로 표시한다.
- 관광지 0건 응답을 성공으로 표시하던 문제를 수정하고, 지역기반 API 호출에 시도별 `areaCode`를 명시했다. 페이지마다 DB 배치 저장을 적용했다. `diagnose-tour.ps1`은 전체 지역 요청과 서울 요청의 HTTP 상태, 전체 건수, 첫 항목 필드명만 출력한다.
- 관광 뉴스는 뉴시스 문화·지방·수도권 RSS에서 수집하고, 기존 기사와 새로 저장된 기사의 건수를 구분한다.
- Maven 단위 테스트 4건 통과. 로컬 Tomcat에서 `/health`, `/attractions`, `/plans`, `/news`, 홈의 HTTP 200을 확인했다. 사용자 실행 Tomcat에서 한국관광공사 API 동기화를 수행해 13,563건을 저장했으며 MySQL에서도 17개 지역·8개 유형의 13,563건을 확인했다. 목록, 서울 필터, 음식점 필터는 각각 HTTP 200과 카드 20개를 반환했다. RSS의 실제 추가 수집 결과는 별도 확인이 필요하다.
- 비공개 여행 계획은 관리자 계정을 포함해 소유자 외에는 목록·상세에서 보이지 않는다. 현재 문서화된 개인정보 범위와 일치한다.
- 카카오맵 활성화는 사용자가 진행하지 않기로 했다. 관광지·여행 동선·Hot Place·좌표 선택 지도는 Leaflet과 OpenStreetMap으로 전환했다. 키 없이 브라우저 인터넷 연결만으로 표시하며, 로딩 실패 시 안내 문구를 표시한다. 홈·관광지·Hot Place·관리자 화면과 공통 CSS를 정리했다.
- 공통 모바일 메뉴와 현재 위치 표시를 추가했다. 관광지·Hot Place의 사진 로딩 실패를 카드 자리표시 화면으로 처리하고, 홈·여행 계획·뉴스·공지·게시판의 제목, 카드, 검색, 목록 간격을 통일했다. 390px 모바일 화면에서 가로 넘침이 없는지 확인했다.

## 현재 구현

2026-10-30 기준, [단계별 구현 계획](03-implementation-phases.md)의 0~5단계 코드를 작성했다. Java 21·Tomcat 11·Maven WAR 기반이며 Servlet(Controller), Service, Dao, Dto를 분리했다. 회원·관광지·여행 계획·Hot Place·뉴스·공지·공유게시판과 관광지 부가 정보 화면을 제공한다. `temp/`와 빌드 산출물은 Git에서 제외한다.

## 확인한 결과

| 검증 | 결과 |
| --- | --- |
| Maven `test package` | 성공. JUnit 테스트 3건 통과, WAR 생성 |

| HTTP 통합 흐름 | 가입·로그인·프로필 수정·여행 계획·방문지 순서 변경·공개/비공개 계획 조회·공유글·공지·Hot Place 사진 업로드·관리자 비밀번호 초기화·탈퇴 통과 |

## 배포 전 확인할 항목

- 공공데이터포털 활용 신청과 키를 설정해 한국관광공사 관광지·사진, 한국천문연구원 일출·일몰, 한국환경공단 충전소의 실제 응답을 검증한다.
- OpenWeather 키로 날씨와 5일 예보를 검증하고 Leaflet 지도와 경로를 실제 브라우저에서 확인한다.
- 실제 배포 MySQL 계정·사진 저장 경로를 설정하고 모바일·데스크톱 화면을 확인한 뒤 요구사항별 실행 화면을 캡처한다.
