# 검증 계획

## 검증 환경

- Java 21, Tomcat 11, MySQL 8에서 WAR를 실행한다. 초기화 SQL을 빈 DB에 적용하고 관리자 계정 생성 절차를 검증한다.
- Service·Dao 단위 검증과 Servlet 요청 검증을 분리한다. 외부 연동은 고정된 정상·빈 결과·오류 응답으로 재현하며, 서비스 키가 준비되면 실제 API와 한 번씩 연결한다.
- 변경 요청의 권한 검사는 화면 버튼 표시만이 아니라 직접 HTTP 요청으로 확인한다.

## 기능 시나리오

| 영역 | 정상 시나리오 | 오류·경계 시나리오 |
| --- | --- | --- |
| 회원·인증 | 가입 → 로그인 → 내 정보 수정 → 로그아웃 → 재로그인 → 탈퇴 | 중복 ID·이메일, 틀린 비밀번호, 세션 만료, 탈퇴 후 로그인 거부 |
| 비밀번호 찾기 | 사용자 요청 → 관리자 처리 → 임시 비밀번호 로그인 → 비밀번호 변경 | 비로그인·일반회원의 관리자 요청 거부, 이미 처리된 요청 재처리 차단 |
| 관광지 | 데이터 수집 → 지역·유형별 목록 → 상세·사진·지도 | 중복 수집, 유효하지 않은 지역·유형, 빈 결과, 사진·좌표 누락, API 중단 |
| 여행 계획 | 관광지 추가 → 날짜·경비·메모 입력 → 순서 변경 → 저장·공유 | 타인의 계획 변경 거부, 비공개 계획 조회 거부, 잘못된 날짜·순서, 중간 저장 실패 시 롤백 |
| Hot Place | 방문지·날짜·유형·설명·사진 등록 → 지도 조회 → 수정·삭제 | 타인 변경 거부, 이미지가 아닌 파일·초과 용량 거부, 파일 저장 실패 |
| 뉴스 | RSS 수집 → 관광 기사 목록 → 원문 이동 | 같은 RSS 재수집, 빈 피드, 잘못된 XML, 원본 제공 중단 |
| 공지·게시판 | 관리자 공지 CRUD, 회원 공유글 CRUD, 공개 목록·상세 | 일반회원 공지 변경·타인 글 변경 거부, HTML/스크립트 출력 이스케이프 |
| 부가 정보 | 날씨·일출·일몰·충전소 위치와 상태 조회 | 키 누락, 제공자 지연·오류, 응답 필드 누락, 관광지 좌표 누락 |

## 화면·품질 확인

- 모바일과 데스크톱에서 메뉴·검색·폼·지도·드래그앤드롭을 키보드와 포인터로 사용할 수 있는지 확인한다.
- 목록의 페이지 이동과 검색 조합, 빈 결과 안내, 입력 오류 메시지, 제출 후 중복 요청 방지(PRG)를 확인한다.
- 비밀번호와 API 키가 로그·화면·Git 변경 파일에 노출되지 않는지 확인한다.
- 관광지 목록은 동기화 작업과 별개로 DB에서 응답하는지, 날씨·충전소 요청이 느려도 주요 화면이 먼저 열리는지 확인한다.
- 외부 정보에는 데이터 출처와 최신 조회 시각이 표시되는지 확인한다.
