## 기존 구현 현황

**[현재 코드]** Java 21·Maven WAR·Servlet 6.1/JSP·JSTL·MySQL Connector/J 8.4.0을 사용한다(`pom.xml`). 연결은 `Database.open()`의 JNDI `java:comp/env/jdbc/EnjoyTrip` 우선, 실패 시 `ENJOYTRIP_DB_URL/USER/PASSWORD` 기반 직접 JDBC다. Connector 버전과 실제 MySQL 서버 버전은 별개다. 초기화 SQL은 수동 실행 대상으로 런타임 자동 마이그레이션은 없다.

`src/main/resources/schema.sql`에는 `users`, `attractions`, `attraction_images`, `plans`, `plan_stops`, `hot_places`, `news`, `posts`, `password_reset_requests`의 **9개 테이블**이 있다. 관광지 기준정보 테이블은 없다. 모든 DAO는 실제 SQL과 PreparedStatement를 사용한다. 조회에 메모리 더미 목록을 사용하는 구조가 아니다.

## 제공 ERD·DDL·덤프 정적 검토

ERD 이미지의 네 엔티티·컬럼과 제공 Schema의 구조는 대응한다. 다만 그림의 관계선만으로 구군의 올바른 지역 소속까지 보장된다고 볼 수 없다.

| 항목 | 확인 사실 | 필요한 처리·결정 |
| --- | --- | --- |
| DB 이름 | Schema와 Dump 본문은 `trip_source`, Dump 헤더 주석은 `trip_source`, 기존 앱은 `enjoytrip` | 실제 `CREATE/USE`를 기준으로 경로 결정. 연결 URL만 바꿔도 호환된다고 보지 않는다. |
| 원본 실행 특성 | Schema는 관광지 네 테이블 DROP 포함, Dump는 DDL 없이 컬럼 목록 없는 INSERT·LOCK TABLES·세션 검사 해제/복구 사용 | 기존 DB에 원본 직접 실행 금지라는 설계 제안. 격리 인스턴스에서 순서·테이블 폭·권한 확인 후 적재한다. |
| 구군 관계 | `gugun_code`는 비고유 인덱스, 같은 코드가 여러 시도에 존재(중복 코드 그룹 25개). `(sido_code,gugun_code)` 중복은 0 | 구군 단독 코드를 전역 고유값으로 만들면 안 된다. Q1 답변에 따라 B안의 복합 UNIQUE·FK 보완 설계에 반영한다. |
| 관광지 ID | 원본 PK `no INT`, 기존 PK `id BIGINT`; 원본 `content_id`는 nullable·비고유, 기존은 NOT NULL UNIQUE | `no=id=content_id`로 간주 금지. 제공 덤프의 `content_id` 중복·NULL은 각각 0이지만 이후 API 데이터까지 보장하는 제약은 아니다. |
| 기준정보 건수 | 시도 17, 구군 234, 유형 8. 각 INSERT 튜플을 문자열·이스케이프를 구분해 집계 | 격리 DB 실행 후 COUNT·중복·참조 쿼리로 재확인한다. |
