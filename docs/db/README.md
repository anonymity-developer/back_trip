# EnjoyTrip DB 확장 구현 계획

구현이 시작되었다. 현재 상태는 [개발 진행 기록](05-progress.md), 직접 실행 방법은 [로컬 테스트 안내](06-local-test.md)를 따른다. 아래의 분석·계획 설명과 ‘변경하지 않았다’는 표현은 최초 계획 수립 시점의 기록이다.

2026-11-06 기준 분석·설계 문서다. `temp/자바전공_enjoytrip_16_06_DB.pdf`와 제공 ERD·SQL을 기존 Servlet/JSP·JDBC 프로젝트에 연계하기 위한 계획이며, **이번 작업에서는 애플리케이션 코드, SQL 파일, DB를 변경하지 않았다.** 아래의 구현 단계와 SQL 검증은 후속 작업이다.

## 개발 목표와 현재 상태

DB 명세서의 중심은 기존 기능의 재작성보다 관계형 모델·정규화·제약조건·DDL·초기 데이터 및 Service/DAO 연동의 완성이다. 기존 코드에는 회원, 관광지, 여행 계획, Hot Place, 뉴스, 공지·게시판의 MySQL 영속화가 이미 있다. 제공 자료의 관광지 기준정보를 연계하고 전체 모델과 제출 산출물을 정비한다.

| 구분 | 확인 결과 및 계획 |
| --- | --- |
| 유지 | Java 21, Maven WAR, Jakarta Servlet/JSP, JDBC, 기존 화면·URL·권한·회원 데이터 구조 |
| 수정 필요 | 제공 관광지 스키마와 기존 컬럼·키 매핑, 구군 코드 적재, 데이터 전환, DB 변경에 영향을 받는 DAO·DTO·동기화 |
| 신규 구현 대상 | 시도·구군·유형 기준정보 연계, 검증 가능한 초기 적재·마이그레이션 절차, 전체 ERD·최종 DDL·DB 단계 검증 기록 |
| 확인 필요 | 덤프와 API의 우선순위, 자료 오류 보정 허용 범위, 실제 DB 환경·제출 규칙 |

제공 덤프의 정적 집계는 시도 17건, 구군 234건, 유형 8건, 관광지 50,915건이다. 이는 SQL 파일의 값 개수이며 현재 실행 중인 DB의 건수가 아니다. 기존 문서의 관광지 13,563건·HTTP 검증 기록은 과거 기록으로만 취급한다. 이번에는 DB 접속·DDL 실행·애플리케이션 실행 테스트를 수행하지 않았다.

## 주요 변경 방향

**기존 `enjoytrip`과 관광지 내부 `id`를 유지하고, 제공 기준정보와 관광지 데이터를 변환 적재하는 방안(B안)을 계획 기준으로 삼는다.** 사용자는 ‘명세에 원형 사용 의무가 없다면 기존 구조 유지 및 제공 데이터 혼합 허용’으로 답했다. 신규 PDF의 본문·요구·산출물 목록에 제공 테이블·컬럼의 원형 사용 의무는 없으며, p.5는 컬럼 추가·요구 개선을 허용한다. 따라서 이 방향은 사용자의 조건에 부합한다.

기존 관광지와 덤프를 `content_id`로 연결해 `plan_stops`·`attraction_images`·상세 URL을 보존한다. 기존 데이터 보존·초기화에 대해서도 사용자는 명세 준수를 요청했다. 명세에 기존 데이터 삭제·초기화 의무가 없으므로 보존을 설계 기준으로 잡는다. 보존 자체를 명세의 필수 요구로 주장하지 않는다. A안은 추후 별도 제출 규칙이 확인되는 경우의 영향 비교 자료다.

구군은 시도와 함께 식별하도록 보완하고, 제공 덤프의 결측값·0 좌표·유형명 불일치를 처리한다. 스키마 원형 사용 의무나 데이터 삭제 허용을 추정하지 않는다. 구군 검색 UI, 새로운 외부 정보 저장 테이블, SGIS 전환 등 명시되지 않은 기능은 자동으로 범위에 추가하지 않는다.

## 사용자 확인이 필요한 사항

질문과 판단 조건의 원본은 [확인 목록](01-requirements.md#확인-필요-사항과-진행-조건)에 있다. Q1~Q4는 사용자 답변과 명세 대조를 반영했다. 충돌 시 기존 ID·비어 있지 않은 값 유지 및 39번 명칭 보정은 승인 후 구현했다. 검증 환경도 MySQL 8.0.46·별도 포트 13307로 확인했다.

남은 확인은 실제 환경 적용 시 DB·파일 상태와 외부 API 키·승인·응답, 최종 GitLab 제출 규칙이다. SGIS·구군 검색 등의 별도 지시가 없다면 기존 기능을 유지한다.

개발·검증은 격리 DB에서 수행했고 기존 실제 DB에는 적용하지 않았다. 전체 산출물은 [DB 제출 자료](../../deliverables/db/README.md), 사용자가 직접 실행하는 방법은 [로컬 테스트](06-local-test.md)에 있다. GitLab 업로드는 수행하지 않았다.

## 권장 구현 순서

요구·보존 정책 결정 → 전체 ERD·DDL 확정 → 격리 DB 적재·검증 → 기준정보 및 관광지 DAO/Service 연결 → 동기화·기존 참조 검증 → 전체 기능 회귀 → 제출 자료 정리 순이다. 세부 단계는 [구현 순서](03-implementation-phases.md)에 있다.
